## Требования к безопасности внешних интеграций
- Строгий контроль доступов - все запросы должны быть аутентифицированы, у субъекта должны быть права на действия с объектом
- Принцип минимальных привилегий - права должны быть выданы только на на, что требуется для взаимодействия, и не более того
- Ограниченное время жизни токенов доступа - токены должны иметь ограничение по жизни и не выпускаться навечно
- Должна быть возможность отзыва токенов доступа - в случае их компрометации
- Трафик должен быть зашифрован с использованием TLS
- Используется белый список ip-адресов для входящих/исходящих подключений
- Между двумя системами установлен приватный канал с использованием VPN
- Для проверки целостности данных в запросах используется подпись HMAC
- Для защиты API используются паттерны Circuit Breaker и Rate Limiting
- Все входящие/исходящие запросы должны логироваться (без чувствительных данных), а так же должен вестись аудит кто/что/когда/с каким результатом совершил действие
- Данные между системами должны передаваться только в том объеме, которые нужны для выполнения операции и не более того
- Должно быть регуляторное соответствие, учитывая работу с персональными данными (биометрия и номера автомобилей)
- Необходим автоматический мониторинг для выявления подозрительной активности и выявления атак

## Протоколы аутентификации и авторизации
OAuth 2.0 и OpenID Connect

## Взаимодействие с внешней платформой
- между системами установлено безопасное соединение через VPN
- входящие и исходящие взаимодействия ограничены белым списком ip адресов
- используется OAuth 2.0 и OpenID Connect для аутентификации и авторизации запросов, используются jwt-токены в качестве токенов доступа (содержат информации о пользователе, а так же о его правах)
- используется отдельный auth-server для взаимодействия с внешней платформой, чтобы был отдельный жизненный цикл токенов которые не связаны с доступами к основному приложению
- запросы подписаны с использованием HMAC
- взаимодействие между системами происходит с использованием REST HTTPS
- для интеграционного взаимодействия используется отдельный сервис-шлюз, его API защищено с использованием Circuit Breaker и Rate Limiting
- другие сервисы системы не взаимодействуют напрямую с внешним провайдером, аналогично в обратную сторону - все взаимодействие только через шлюз
- все запросы/ответы логируются, а также ведется аудит и автоматический мониторинг
